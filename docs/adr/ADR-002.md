# ADR-002: API shape: one FastAPI service, no separate BFF

- **Status:** Proposed
- **Date:** 2026-10-03
- **Source:** Architecture views deck and HLD (decision register)

## Context
Options considered: Separate BFF + core API; single API behind a web proxy.

## Decision
One FastAPI service on internal ingress, behind nginx.

## Rationale
Chat is read-only and synchronous, with no irreversible actions, and platform auth handles the session; a second service adds a hop with no benefit.

## Consequences
If approvals or write-backs arrive later, split out a BFF.
