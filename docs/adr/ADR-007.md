# ADR-007: Hybrid fusion: weighted RRF in the api over store-native legs

- **Status:** Proposed
- **Date:** 2026-10-03
- **Source:** Architecture views deck and HLD (decision register)

## Context
Options considered: In-memory BM25 + EnsembleRetriever; store-native single hybrid query; store-native legs fused in the api.

## Decision
Run store-native dense and keyword queries; fuse with weighted RRF in the api.

## Rationale
Keyword index persists with the store; per-leg scores are visible on every request; item-ID weighting behaves identically on both backends.

## Consequences
Two index round trips per question (about 20 ms).
